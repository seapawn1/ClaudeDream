# TestPlan · Prototype-01 判据与测试剧本

**这是什么**：Friday Test 的施工图，回答三件事——**怎么算过**（§1 硬判据：五条验收信号的操作化）、**怎么测人**（§2–§4 行为观察与剧本）、**怎么宣判**（§5：Test 的产出是宣判本次 design 是否通过）。

**方法立场**（Testing with Users 纪律）：用户环节**不是验收仪式**——show don't tell、请用户边做边说、不领路不纠正、以问答问；宣判发生在环节结束之后，由 Decider 综合硬对账与行为观察下判。测的同时继续学用户：每个负面反应都是对"长期用户"这个角色的新认识，不只是对方案的扣分。

## §1 硬判据 H（机械对账——原型施工验收阶段即测，不需用户在场）

| # | 源信号 | 操作化判据 | 测法 |
|---|---|---|---|
| H1 查全 | 不引用过期事实 | 5 条种植腐烂**全部**被处置（删/隔离/标注任一算处置；处置方式与 rot-manifest 预期不符的记为偏差单独讨论） | 对 rot-manifest 对答案卡逐条对账 |
| H2 查准 | 与项目现状同步 | 健康记忆**零误删**；CLAUDE.md 过期命令被正确修正（run-01 阀门开） | git diff 对账 |
| H3 溯源 | 条条可溯源 | 报告每笔四要素齐全（动作/判据编号/证据/回滚命令）；3 个抽查点命令**执行即复现** | 逐笔审计 + 实测执行抽查命令 |
| H4 解释权 | 用户握有最终解释权 | 单条回滚实测恢复；关阀梦（run-02）CLAUDE.md 零 diff 且报告出现"建议（未动）"；熔断线调低后重跑实测中止并 reset 回快照 | 实操验证 |
| H5 契约 | （工程底线，源自硬约束4） | 梦后 MEMORY.md 契约完整（索引 ↔ 文件双向对账零漂移）；`dream:` 单提交 `git revert` 一步整梦撤销实测成功 | 脚本校验 + 实测 revert |

**靶外声明**（不测不装测）："不重复提问"属 S10–S11 取用段，留 Target-2；十格中 G10"数周后复利"单次 Test 不可观测，属长期使用验证——两者记入 DesignMap 缺口注，不算 Prototype-01 的账。

## §2 行为观察 O（用户环节，Friday 执行）

| # | 观察 | 想学到什么 | 负面形态 |

| O1 30 秒版 | 实际计时 + 读完的情绪（安心/紧张/无感） | 报告形态承载得起信任吗（Test 关键观察①） | 读不完，或读完反而更紧张 |

## §3 用户与剧本

**真实用户：seapawn 走全程 G1–G9**（G1/G2 以 run-01 既成产物代入场景："你昨天在 acme-api 收工，夜里梦跑了"）。逐格任务：

| 格 | 任务 | 主持要点 |
|---|---|---|
| G3 | 看开场一行提示，念出第一反应 | 不解释这行字是什么 |
| G4 | 打开梦报告 | **开始计时**；请他边读边说 |
| G5 | （不提示）观察他是否主动执行抽查命令 | 若 5 分钟未动，再问"你会核实吗？怎么核实？" |
| G6 | 读 connection 全文 | 问："这条对你有用吗？为什么？" |
| G7 | 挑一笔不服的，实操单条回滚 | 观察他找回滚命令花多久 |
| G8 | 打开阀门配置，关掉 `claude_md_edits` | 出示 run-02 报告："这是关阀之后的世界" |
| G9 | 读"待你裁决"节，说出裁决 | 问："你期望这个裁决何时生效？" |

**模拟用户（3 个 subagent 人格，各自独立拿真产物文本走 G3–G7）**：

| 人格 | 设定 | 补的样本 |
|---|---|---|
| P1 审计型 | 十年老工程师，曾被 AI 工具误删过东西，默认不信、逐笔核 | O2 的上限：最挑剔的人能不能被证据说服 |
| P2 赶时间型 | 交付期中，只肯给 30 秒，超时就关 | O1 的下限：最不耐烦的人带走了什么 |
| P3 新接手型 | 接手 acme-api 两周，记忆库不是他攒的 | 所有权视角：别人攒的记忆被 agent 改，敢不敢收 |

**模拟用户效力声明**：LLM 扮演产不出真实情绪证据（推测），其结论只作参考样本，权重低于 seapawn 的真人反应；三份 Matrix 与真人 Matrix 分开归档、不合并统计。

## §4 Feedback Capture Matrix（每位用户一份）

四象限实时填：**＋** 喜欢/注意到 ｜ **Δ** 建设性批评 ｜ **?** 疑问 ｜ **💡** 新想法。纪律：不当计分卡用——负面证据与确认证据同等入格；每格都争取有内容，只有＋的一份 Matrix 是失败的记录。

## §5 宣判规则（用户环节之后，Decider 拍板）

| 结果 | 条件 | 去向 |
|---|---|---|
| **通过** | H1–H5 全过，O1–O4 无重大负面 | Design 通过 → 进产物开发（Scrum 段） |
| **带条件通过** | H 全过，但 O 有**定向**负面：O3 废话 → 剥离 wiki 层（Sketches 附注已备案的退路）；O1/O2 负面 → 报告形态重画 | 按条件修改 → Prototype-02 只复测该项 |
| **不通过** | H1 或 H2 失败（体检-处置主干不成立），或 O4 显著负面 | 回 Ideate 重新发散 |

**R6 专项条款**：O1 与 O2 同时负面 = "30 秒版也没人读"成立 → 冲刺问题 3 的答案是"事后回看**不够**"，须重新设计送达机制本身，不是改报告排版能解决的。
