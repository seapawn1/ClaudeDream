`scrum/.IDEO/design-sprint/` 顶层两份总图（DesignMap / DesignReview，README 为导航）的蒸馏，2026-08-30 仓库重构落账。Target-1 主靶档案的细节蒸馏见 [[design-sprint-target1-distilled]]。效力顺序：reference/ 原料 > design-sprint 蒸馏 > 本记忆；带「推测」标注的判断不作决策依据。

## 长期目标（原句；Vision 兼 Product Goal）

> 任何长期使用 Claude Code 的人，开新会话时 agent 都像昨天刚一起工作过；而且越用越懂你——记忆产生复利，agent 能连起你自己都没连起的线索。

**双承诺必须分开裁**：项目侧（像昨天刚一起工作过）vs 个人侧（越用越懂你/复利）。结算（2026-08-02）：项目侧证成（真人原话「更懂我们的项目了」）；个人侧机制存在且有效（connection 被模拟用户判「干货」）但「懂你」未测——待 S4 底片层接通 + 跨周长期使用剧本，是「未测」不是「失败」。

## 11 步数据流（闭环非直线，复利靠回环叠加）

S1 开会话热身 → S2 干活产生信号 → S3 实时记零散记忆（官方 auto-memory 契约：一记一文件 + MEMORY.md 纯指针索引——硬约束，沿用不改） → S4 会话流落盘（机械压缩底片层，Karpathy raw/ 形制：只追加、零 API、不判断） → S5 Dream 触发（插件无免费离线时刻；hook 零 API 写标记 + 分离进程判条件跑 SDK + 防递归） → S6 体检 → S7 整合（memory 文件系统 + CLAUDE.md 一起改） → S8 写梦报告（人不参与梦，报告即汇报） → S9 git 提交（dream: 单提交 = 回滚原子） → S10 新会话找对容器取索引 → S11 引用前现场校验 → END 回环。
**两条横向批注（地基限制）**：①取用在架构上不被保证——记忆是 context 非 enforced configuration，S11 只是运行时最后一道拦截；②记忆容器按工作目录路径字符串键控——项目改名/搬盘会静默孤立记忆（本项目 2026-07-29 搬盘实际发生过）。

## 四条冲刺问题与结算答案

1. **过期**（权重第一，主答在 Target-1）：判据 = 项目现状 + git 讣告（不拿记忆互相投票）；错删 ≫ 错留，落成结构（隔离优先 / feedback 类永不自动删 / 拿不准一律 quarantine）；谁有权删 = **机械证据开票、LLM 无票、引擎执行**（全方案最硬的一条）。未尽：M4「搭便车事实」盲区——实体死了 ≠ 记忆里所有事实都死。
2. **取用**：整条靶外转 Target-2（S10–S11）。与问题 1 的分界 = 离线主动体检 vs 运行时引用前校验，两处都要做、解法不同。前提（整合先做对）已具备。
3. **信任**（冲刺最重要发现）：四位被试四种态度（真人正面 / 审计观察期 / 赶时间有条件允许 / 新接手先只报告）→ 收束结论：**「事后回看能否替代事前批准，取决于回看的可查证性」**——报告告诉用户它做了什么 ≠ 让用户能查证它做了什么，前者是产品后者才是信任；日常没人核报告（抽查点价值 = 存在即安心），正因此必须经得起真查。
4. **所有权**：阀门（CLAUDE.md 默认改、可关）+ L0–L3 分级处置 + 势力范围声明，三件套划界。实证：真人关阀后判「就应该如此」；两场真梦都主动认边界（发现矛盾定谳钥匙是代码文件 → 判「删代码超出势力范围」请用户动手）——agent 自觉尊重边界比工程强制更能建立信任。未尽：observe-only 模式待裁。

## 五条验收信号结算（2026-08-02）

不引用过期事实 ✅（缺口 = M4 盲区）｜与项目现状同步 ✅（36 健康零误删）｜条条可溯源 ⚠️ 形式过、实质待改（C2/C3）｜用户握最终解释权 ⚠️ 部分过（C1）｜不重复提问 ⬜ 未测转 Target-2。两条打折恰都在「信任」主承诺上，且非执行不力——是判据当初写得太松，被审计人格撞破。

## 三条最值钱教训（反直觉）

1. **撤销键的工程质量必须高于删除键**——把心思花在「怎么安全删」，却让回滚停在「报告里贴一行 git 命令」，审计型用户一眼看穿。
2. **模拟用户测出的缺陷远多于真人**——不是 LLM 比人聪明，是人格约束逼出了真人不会采取的视角（真人是共同设计者看什么都顺眼）。
3. **安全阀只能用故障注入证明**——合作型 agent 永远碰不到工程熔断线，必须写作恶假 agent 走真实审计路径。

## 方法论六条（DesignReview §6，可复用）

真人测体验、模拟用户测缺陷（不可互替，成本差一个量级）／真人被试偏倚显式记账（其「赞」证据力低于「追问」）／布景数据必须从真产物机器提取不可手写／安全阀故障注入建议进产物 CI／白板产物走 plan-view 逐段批注（多次拒绝审批 = 深挖信号）／四派竞争草图 + 杂交定稿（真隔离 subagent 各画一派，比一稿反复改更易暴露结构性差异）。

## 冲刺过程与去向

五天路线：Define → Ask the Experts（四模块：官方机制考古/前人深读/社区调研/决策者访谈）→ POV+HMW（40→21→8 条；**未选中候选未落盘，复查须重跑**）→ Pick a Target（长期用户 + S6–S8 整合段）→ Ideate（三场闪电演示 → 四派竞争草图 → wiki 主体杂交）→ Prototype（腐烂库 + 梦引擎，三场真梦）→ Test（真人十格 + 模拟人格三格）→ 三级 Review。三个转折点：圈靶圈在唯一写文件段 / 杂交选 wiki 派（唯一兑现复利）/ 模拟用户把「施工验收全过」撕开三道信任口子。
**去向**：①产物开发入场条件 = C1–C7 改造（C1/C2/C3 是信任兑现前提）+ S4 机械压缩底片层 + canUseTool 结构缴械；②Target-2 取用段（S10–S11 + 身份族 HMW）为候选下一靶；③待 Decider 另裁三项：observe-only 模式 / 梦间方差可否接受 / 个人侧复利怎么测。
