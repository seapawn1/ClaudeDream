收到独立 review（D3 review、代码审查类 agent）的结果后，先把发现整理成清晰的报告呈给 PO，不要自己直接动手改；等 PO 看完、给出方向再继续。

**Why**：Sprint-1 骨架回环执行中，三轮 D3 review 里前两轮我都是"收到发现 → 自己判断 → 直接修 → 重测 → 再送审"全自动循环，没有在每轮之间跟 PO 同步。seapawn 在第三轮送审后明确要求"先不着急修改，整理 review 内容然后向我报告"——这是对已经发生了两轮自主循环之后的明确纠偏，说明 PO 想在关键节点（尤其是发现累积到一定程度、或审查本身变成多轮拉锯时）保留"先看、再定方向"的控制权，不是默认信任我自主循环到底。

**How to apply**：任何一轮独立 review/审查类 agent 返回结果后，默认先做"整理+汇报"这一步（结论先行：核心发现是什么、严重程度、我倾向的判断），再等 PO 明确的"去修"或别的指示，不要把"汇报"和"开始修"揉进同一个动作里自动连着做。多轮审查-修复循环如果开始拉长（例如同一处反复被打回），更要主动升级为"先汇报"而不是"再战一轮"——这条本身也适用于本轮之后的场景，不只是这一次。
