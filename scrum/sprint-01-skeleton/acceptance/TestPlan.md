# Sprint-1 验收 TestPlan · 骨架回环怎么算过

**这是什么**：Sprint-01-skeleton 的验收考卷，回答三件事——**怎么算过**（§1 硬判据 H：13 条 AC 的操作化）、**怎么测**（§2 四个场景 + §3 对实现的要求）、**怎么宣判**（§5）。出卷人是 Scrum Master 会话 + Product Owner 批准，答卷人是落地 [SprintBacklog.md](../SprintBacklog.md) 的 Product Developers——**出卷与答卷分离**，避免自己拟定自己过。

**测的是什么**：[Sprint Goal](../SprintBacklog.md) 一句话——「环必须真转一圈」。判据全部对着**回环转不转、围栏拦不拦、证据留不留得下**，**不测引擎判得准不准**（本轮是占位引擎，见 §4 靶外声明）。

**方法立场**：判据二元可判，不留"基本可以"的空间；能自动跑的写进 [verify.mjs](verify.mjs)，不能自动跑的（人眼确认项）在 §2 给操作步骤，不假装自动。考场每次验收前重建，脏考场上的绿灯不算数。

## §2 怎么跑

```bash
cd scrum/sprint-01-skeleton/acceptance
node testbed/build-testbed.mjs   # 重建考场（每次验收必做，脏考场上的绿灯不算数）
node verify.mjs                  # 跑 §1 全部自动判据，输出 H 逐条红绿表
```

四个场景的实际执行顺序是 **A → D → B → C**：D 要在梦刚跑完的干净状态下 revert，B/C 会往 `.claude/dream/` 里写标记与日志，先跑它们会让 revert 撞上「本地改动会被覆盖」而假摔。

**考卷自己的体检**：`node selftest/run-selftest.mjs`。一份从没跑过主体逻辑的验收脚本不配当验收标准——DoD·D1 同样约束考卷自己。自检拿 `selftest/fake-plugin`（一份把回环形状走完、但不做任何真体检的假实现）跑四轮：正向一轮应除三条人工项外全绿；三轮负向分别把快照改成 `git add -A`、把梦拆成两笔提交、无视冷却期，对应的 H-A4 / H-A7 / H-B1 **必须转红**。出卷时四轮均已通过。假实现只为验卷存在，不是产品实现的参考架构。

**考场**：`testbed/build-testbed.mjs` 确定性生成 `testbed/dream-lab/`——一个虚构的本地记账 CLI 项目（`ledger-cli`），含真 git 仓库（5 个提交）、8 条记忆 + MEMORY.md 索引、CLAUDE.md、白名单外的源码文件。**本考场不种腐烂**：Sprint-1 的占位引擎不判内容，考场提供的是结构齐全的场地，任何内容 diff 都应是梦造成的。`.claude/dream/` 故意不存在——它该由梦第一次跑时自己建。生成物不入库（`testbed/.gitignore`）。

**人工核对清单**（脚本查不了的三项，验收当场做）：

1. **H0**：在 `testbed/dream-lab/` 里起一次 Claude Code，确认插件加载无报错、无警告；
2. **H-A8**：场景 A 跑完后在考场新开一次会话，确认开场真的出现那一行梦提示；
3. **H-C3**：读一遍 spike 记录，确认结论明确、走的哪条路有交代。

## §3 对实现的要求（答卷方须提供）

出卷时插件还没写，考卷不能猜实现细节。以下三项是**卷对实现提的接口要求**，developers 交付时一并满足——满足与否本身不是判据，但缺了则考卷跑不起来。

### 3.1 适配层 `adapter.json`

考卷通过一份适配声明找到实现的入口与产物位置，格式见 [adapter.example.json](adapter.example.json)。developers 完工时把它复制为 `adapter.json` 并填实。`verify.mjs` 找不到它会直接报错退出，不会假装通过。

### 3.2 故障注入入口

**这是本卷对实现提的唯一额外约束，理由要点明**：合作型 agent 永远不会主动越界，靠正常跑一场梦证明不了围栏有效——设计冲刺原型阶段已实测过这一点（结论见项目记忆 `headless-claude-dir-protection`，做法见原型 `engine/rogue-dream.py`）。因此实现须提供一个**蓄意作恶模式**入口（命令、环境变量或参数均可，在 `adapter.json` 的 `commands.runDreamRogue` 声明），令梦进程尝试写一个白名单外文件。没有它，H-C2 无法验证，围栏等于没测。

### 3.3 两处本轮不预设的地方

- **报告文件是否与记忆改动同笔提交**：SprintBacklog·04.3·AC3 明写留待 C7 决定，本轮不写死。H-A7 只判"记忆与 CLAUDE.md 收为单笔"，报告在哪笔不判；实现选了哪种，在 `adapter.json` 的 `report.commitPolicy` 声明一下，供 Review 时说明。
- **canUseTool 放行还是走退路**：AC0 的 spike 结果决定，两条路都可能算过（H-C3 判的是"结论在案、退路有交代"，不是"必须放行"）。

## §4 靶外声明（不测不装测）

- **引擎判得准不准不测**——本轮是占位引擎，查全查准归下一个 Sprint（PBI-02）。届时可继承设计冲刺旧卷的 H1/H2 判据（`.IDEO/design-sprint/.../Prototype-01-FirstDream/test/TestPlan.md`），以及旧考场 `acme-api` 的种植腐烂与对答案卡。
- **取用段 S10/S11 不测**——属 Target-2，架构图里已标靶外。
- **长期复利（OD1「越用越懂」）不测**——单次验收不可观测，属 Definition of Outcome Done 的长期观察项。
- **梦报告好不好读不测**——报告形态的用户验证在设计冲刺已做过（O1–O4），本轮只判六节骨架在不在。

## §5 验收规则

| 结果 | 条件 | 去向 |
|---|---|---|
| **过** | H0–H-D1 全过（含三项人工核对） | Sprint 收口，卷面结果作为 Sprint Review 的检视证据 |
| **打回** | 部分不过，但场景 A 成立（环转得起来） | 退回 developers 修，**Sprint 内**修完重跑，不算 Sprint 失败 |
| **上报** | 场景 A 不成立（环根本转不起来），或多轮打回仍不过 | 摊到 Product Owner 面前裁决 Sprint 去留——这是 Scrum Master 的上报义务，不替团队消化 |

**与 Definition of Output Done 的关系**：本卷即 D1（一键重跑的验证）在 Sprint-1 的兑现物；D2（不破坏 auto-memory 契约）本轮由考场结构隐含覆盖——梦只在白名单内动手，MEMORY.md 契约的正面校验待引擎进场后补；D3（独立 review）在 H 全绿之后另行进行，不由本卷代替。

**考卷够不着的地方（交给 D3，别指望绿灯替它背书）**：考卷从**行为**判定——文件在不在、提交是不是一笔、越界拦没拦住。它判不了**真实性**：一份把回环形状演一遍的假实现同样能把 H 全部点亮（出卷自检里的 `fake-plugin` 就是活证）。所以 H-A3「经 Agent SDK 起梦」只做到静态引用检查；「梦是真的跑在 SDK 里、canUseTool 是真的在守门、占位引擎是留了装引擎的位置而不是空壳」这类判断属于代码审查的职责，由 D3 的独立 review 认。**H 全绿 ≠ Done，全绿且过 D3 才是 Done。**
