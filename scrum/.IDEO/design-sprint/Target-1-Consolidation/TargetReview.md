# TargetReview · Target-1 整合段结算

**结算日**：2026-08-02　**依据**：[TargetMap.md](TargetMap.md) 的 Goal 与通过标准；证据为 [Prototype-01-FirstDream/verdict.md](Prototype-01-FirstDream/verdict.md)、[artifacts/audit-notes.md](Prototype-01-FirstDream/artifacts/audit-notes.md) 与 `Prototype-01-FirstDream/test/` 下四份测试记录。

> **一句话结论：达标放行，带七条改造。** 靶设的三步（体检 → 整合 → 留证）全部在真实腐烂库上跑通；"信任"的兑现打折——不是因为没做，是因为做出来的凭证**经不起真查**。

## 一、Goal 逐句对账

TargetMap 的 Goal 原句拆成四个承诺，逐一裁：

| # | Goal 承诺（原句节选） | 裁定 | 证据 |
|---|---|---|---|
| ① | "面对一个已经腐烂的记忆库，找出站不住的条目" | **兑现** | H1 全召回 5/5，与 [rot-manifest](Prototype-01-FirstDream/testbed/rot-manifest.md) 对答案卡逐条一致；机械层 M1–M5 在假库上零误报 |
| ② | "动手改掉（memory 文件系统与 CLAUDE.md 一起）" | **兑现** | H2 零误伤（36 条健康记忆一条未动）；L2 阀门双向实测——开阀改对种植行、关阀零 diff 且降级为"建议（未动）"+ 记忆侧 `contradicts` 标注 |
| ③ | "留下一份人能看懂的变更凭证" | **部分兑现** | **形态成立**：四位被试全部读完，P3"从恐慌到能思考的全部距离"；**证据形态不成立**：P1 核实证据是转述非执行日志（同篇混 POSIX 与 PowerShell、零退出码零时间戳），三个抽查点有一个永不失败 |
| ④ | "'信任'二字在此兑现：用户敢让 agent 自己删，且事后看得清、退得回" | **部分兑现** | **"敢让删"成立**：真人 G7 实操"飞速、功能很强"；熔断/铁律/越界三阀经故障注入实测拦截并整梦回滚；**"退得回"有结构缺陷**：单条回滚跨笔连坐（已核实 `api-rate-limit-policy.md` 被两笔改过），撤一笔会静默丢另一笔 |

**②的附注（差异化赌注的结算）**：官方提示词明写 `do NOT edit CLAUDE.md during a dream`，我们**反着做了**，依据是 git 回滚层。真人 G8 亲手关阀后判"符合预期，就应该如此"——**赌注成立**：用户要的不是"agent 永不碰"，是"碰之前我有开关、碰之后我看得见"。

## 二、通过标准四项核销

TargetMap 通过标准：*"一次整合能在真实腐烂的记忆库上跑通并产出三样东西……删除决策须可辩护……具体阈值与'哪些必须问、哪些随手处理'的分界在 Ideate/Prototype 阶段声明"*。

| 要求 | 状态 | 落在哪 |
|---|---|---|
| 改动后的记忆文件系统与 CLAUDE.md | ✅ | run-01 真跑：42 → 40 条，CLAUDE.md 一处修正；[dream-full.diff](Prototype-01-FirstDream/artifacts/run-01/dream-full.diff) |
| 一份梦报告 | ✅ | 六节齐全；[run-01 报告](Prototype-01-FirstDream/artifacts/run-01/2026-08-02-express-era-cleanup.md) |
| 一个可回滚的 git 提交 | ✅ | 快照 + `dream:` 单提交；`git revert` 实测成功（H5） |
| **删除决策须可辩护** | ⚠️ **打折** | 判据编号 + 证据链存在（每笔四要素齐全），但**证据是转述而非执行记录**（C2）、抽查点有一条循环论证（C3）。"可辩护"目前只到"自洽"，未到"可查证" |
| 阈值与"必须问/随手处理"的分界须声明 | ✅ | L0–L3 四级处置表 + 六键阀门配置，且经实测（G8 关阀降级、G9 待裁决节） |

> **结论：形式上四项全满足，实质上第 4 项打折。** 这一条打折不是执行不力，是**判据当初写得太松**——H3 只要求"抽查点命令能执行且复现"，没要求"证据本身是执行产物"。判据的漏洞被 P1 的审计人格撞破，这正是 Test 存在的意义。

## 三、靶内未决与风险结算

**S4 原料层定位** —— **已拍板**（2026-08-02，Friday Test 中裁定）：取 **A 机械压缩底片层**（Karpathy LLM Wiki 的 `raw/` 形制：只追加、不可变、零 API；提炼留在梦内，梦是全系统唯一不占用户时间的 LLM 时刻）。B 路线（compiler `flush.py` 的 SessionEnd LLM 提炼）落选：每次收工烧 API 且判断点前移。此裁决同时是 G9 回程 bug 的修法——梦 D3 定向时先翻底片找用户留话。

**复利缺口** —— TargetMap 段末记的"长期目标的复利当前无兑现处"，本轮**部分补上**：connection 机制真跑产出，三位模拟用户判"干货"（P2"全场唯一的干货"、P3"唯一让我觉得它在帮我而不是替我做主的东西"），**R1（废连接毁信任）不成立，wiki 层保留**。但缺口未完全关闭：真人只给"还可以"，且个人侧"越用越懂你"本轮未测。

**R1–R6 六条自报风险现状**：

| 风险 | 现状 |
|---|---|
| R1 LLM 量产废连接 | **不成立** —— 三份记录判干货；但须贴身份证（C4） |
| R2 官方重写记忆文件剥掉 wiki 器官 | 未触发（官方 gate 仍未放行） |
| R3 小库冷启动孤儿噪音 | 已缓解 —— M2 降为"仅观察不开票"，<15 条整体禁用 |
| R4 官方 gate 放行后双写冲突 | 未触发，锁文件互斥留产物阶段 |
| R5 偏好/教训类记忆机械判据失明 | 按设计走 L3 保护；G9 实证 feedback 类正确进入"待你裁决"而非被处置 |
| R6 30 秒版也没人读 | **部分成立的反面**：四人全读了，但**没人核实**（O2 全员未接或核不成）。"没人读报告"不成立，"没人验证报告"成立 |

**新增风险（本轮 Test 发现，进产物 backlog）**：M4 判据的"搭便车事实"盲区——实体死了不等于记忆里所有事实都死了（P3 提出，以被删的 auth 笔记中 `{ error: 'unauthorized' }` 响应契约为例）。

## 四、四条冲刺问题在本段的结算

**问题 1 · 过期（本段主答）** —— 三个子问题都有了实际答案：
- *判据从哪来*：**项目现状 + git 讣告**。机械层五判据（M1–M5）零 LLM 成本先跑，其中 M4 用 `git log --diff-filter=D` 把"实体 0 命中"升级为"确凿"，兼防改名误判；
- *错删和错留哪个代价更高*：**错删远高**，已落成结构——隔离优先（`delete_policy: quarantine-first`）、feedback 类永不自动删、拿不准一律 quarantine；
- *谁有权删*：**机械证据开票、LLM 无票、引擎执行**。这是本段最硬的一条设计——梦 agent 在结构上没有删除能力，只能提交申请单，引擎逐笔校验后代为执行，非法申请整梦回滚（故障注入实测）。

**问题 4 · 所有权** —— 阀门 + L0–L3 + 势力范围三件套。实证两处：真人 G8 关阀后判"就应该如此"；两场真梦**都主动认边界**——发现 `jest.config.cjs` 是矛盾定谳的钥匙，但都判定"删代码文件超出我势力范围"，转而请用户动手。**agent 自觉尊重边界比工程强制更能建立信任**（P1："一个自动化工具主动划出'这我不碰'的边界，比它论证'这我碰了但很安全'有用一百倍"）。

**问题 3 · 信任** —— **本段只制造证据，不结案**（TargetMap 原本就这么定的）。四位被试给出四种态度：真人"更懂我们的项目了"、P1 观察期、P2 有条件允许、P3 先只报告。收束结论：

> **事后回看可以替代事前批准，前提是回看经得起查。** 今天的报告告诉了用户它做了什么，但没让用户能**查证**它做了什么——前者是产品，后者才是信任（P1 收束句）。

**问题 2 · 取用** —— 整条靶外，转 Target-2。本段做对是它的前提，此前提现已具备。

## 五、结论与去向

**Target-1 达标放行**，带 [verdict.md](Prototype-01-FirstDream/verdict.md) 第三节 C1–C7 七条改造进入产物开发 backlog（其中 C1/C2/C3 是"信任"承诺的兑现前提）。另两项已拍板的产物阶段工作：S4 机械压缩底片层、Agent SDK `canUseTool` 结构缴械。

**Target-2 取用段（S10–S11）** 为候选下一靶，依据仍是 DesignMap 的判断："整合错了，取用侧校验再准也只是准确地取到一条错记忆"——该前提现已解除。
