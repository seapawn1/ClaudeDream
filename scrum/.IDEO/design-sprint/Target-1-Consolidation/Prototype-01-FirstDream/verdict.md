## 一、判决

> **带条件通过。** 定稿方案的**主干成立**——体检判据、分级处置、阀门、git 回滚层在真实腐烂库上跑通且经故障注入验证；**兑现层不成立**——报告的证据形态、回滚的隔离性、机器推论的身份标识三处有结构性缺陷，且三处都恰好落在"信任"这个 Target 的核心承诺上。
>
> **去向（依 Decider 2026-08-02 裁决）**：**设计冲刺阶段在此结束**，不再开原型轮；第三节 C1–C7 七条改造**转入产物开发 backlog，作为 Scrum 段的入场条件**，其中 C1/C2/C3 是"信任"承诺的兑现前提，须在首个可用版本前完成。

## 四、待 Decider 另行裁决的三项（本宣判不预设）

1. **observe-only 模式**是否进产物：P3 论证它"不是降级，是功能不同的产品——把插件从处置人变成导游"，且给出分级放权路径（先放"加"类，删/合并手动）。可能是**新用户 onboarding 的主入口**，也可能是过度设计；
2. **梦间方差**：三场梦对同一库处置不同（合并方向相反、connection 选题不同）。都合法、信息都保全，但"同一天两次梦结果不同"是否可接受；
3. **个人侧复利如何测**：O4 项目侧已证成，"越用越懂你"须待 S4 接通后设计新剧本（可能需跨周的长期使用观察，非单日 Test 可判）。

## 五、本次 Test 的方法论收获（存档）

1. **模拟用户的价值被严重低估**：三个人格产出的可核缺陷数量远超真人环节。原因不是 LLM 比人聪明，是**人格约束逼出了真人不会采取的视角**——真人是共同设计者（看什么都顺眼），P1 被要求"逐笔核对"就真的去 diff 里抠 hunk 头。**建议固化为流程：真人测体验，模拟用户测缺陷。**
2. **真人被试的偏倚必须显式记账**：seapawn 深度参与设计且测前听过实现讲解，其"点赞"的证据力低于其"追问"的证据力（G9 那句"你读了我们的对话吗"引出了 S4 拍板）。
3. **主持人布景失误两处**（提示行文件名、隔离数）已在记录中认账；教训：**布景数据必须从真产物机器提取，不可手写**——这与 C5 是同一条原则的两面。
4. **安全阀只能用故障注入证明**：合作型 agent 永远碰不到熔断线（run-03 实证）。建议进产物 CI。
