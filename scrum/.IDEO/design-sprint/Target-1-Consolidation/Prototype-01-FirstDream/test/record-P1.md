## ✅ 已核实的结构性缺陷（进宣判，优先级从高到低）

### 1. "单条回滚"做不到单条隔离——会静默丢数据

`api-rate-limit-policy.md` 在本梦被**两笔不同动作**改过：合并（description 重写 + `merged_from` 登记）与加反链（正文追加"相关风险见 [[connection-…]]"）。二者落在同一 diff hunk 里。后果（主持人核实）：

- 撤 connection 那笔的命令含 `git checkout <sha> -- api-rate-limit-policy.md` → **连带把用户认可的合并一起撤回**，而 `rate-limiting-rules.md` 已删不在还原列表——**合并进来的信息静默丢失**；
- 反向撤合并 → 反链消失，但 connection 文件仍写着 `[[api-rate-limit-policy]]` → **制造新断链**。这场梦刚花一笔修断链，它的回滚命令会造出新的。

**根因**：报告按"逻辑笔数"切，git 按"文件"切。一个文件被 N 笔动作改过，就不存在真正的单条回滚。**"单条回滚"这个词承诺了它做不到的隔离性**——而这正是 G7 里真人被试盛赞"功能很强"的那个功能。

### 2. 证据是转述，不是执行日志

同一份报告混用 POSIX（`test -e`、`grep`、`git grep -c`）与 PowerShell（`Test-Path jest.config.cjs` = True）两种方言 ✅（主持人在报告原文确认）；全篇**零原始输出、零退出码、零时间戳**。"我没有任何办法区分'它跑了这条命令'和'它写下了它以为这条命令会返回什么'——对 LLM 驱动的进程，这就是全部的区别。"

**这一条直接命中 H3（可辩护）判据的软肋**：H3 施工验收时只测了"抽查点命令执行即复现"，没测"证据本身是否为执行产物"。

### 3. 抽查点 2 是永远不会失败的检查

`grep -n "build" package.json README.md CLAUDE.md`（"应只见 pnpm"）——CLAUDE.md 已被本梦改成 pnpm，此检查必过 ✅。它验的是"改完自洽"，不是"改动当初有依据"。**给一个必过的检查项比不给更糟：不给我知道自己没验，给了我以为验过了。** 抽查点 3（`git log --all` 应无输出）以"无输出"当存在性证明，措辞"从未入库"超出证据强度。

**设计规则由此确立**：抽查点必须以梦前状态为基准（`git show <pre-sha>:<file>` 起手），凡能被梦后状态自动满足的检查不许写进抽查点。

### 4. 报告动词覆盖不住 diff 范围

"修断链：移除 `[[express-migration-plan]]`" 实际是**整句正文改写 + 塞入提交号 + 新增一句结论性断言**（"细节以 d6fba0b 提交为准"）✅。"报告用一个小动词覆盖一个大动作。单看报告我会放行，看了 diff 才发现范围不对——而绝大多数人不会看 diff。"

### 5. 30 秒版漏掉唯一的"写入新主张"动作

30 秒版四条里没有"新连接"三个字 ✅。"删除有 git 兜底，**新增没有任何兜底**——最该进摘要的恰恰是它。"摘要让人以为动了 5 个文件，实际 **13 个** ✅（diff 计数确认），其中 5 个是往用户原有记忆正文里追加句子。

### 6. connection 的 description 有无源升级："单点"

实际 description ✅：「限流的正确性与可用性都押在一个免费额度的 Redis **单点**上」。三条源记忆均只提"免费额度"，**没有一条说 Redis 是单实例**——"单点"是梦自己加的。而 description 恰是写进 MEMORY.md 索引、天天被扫到的那行。**"不是删文件，是往事实库里掺一个我从没说过的形容词。"**

### 7. 机器推论无身份证（与 P3 独立同源）

connection 通篇是假设（满篇"若""可能"，maxmemory-policy 与 fail-open 两个关键事实均未查证），标题却是"合并结论"；frontmatter 只有 `type: connection`，**无 confidence / hypothesis / 生成日期 / 来源标记**。"六个月后它和我亲手写的 41 条长得一模一样……**这比它删两个文件严重：删错了我能从 git 捞回来；掺进来一个读起来像事实的猜测，它会一直复利，而且没有任何一次 diff 会提醒我。**"

### 8. `git revert` 会销毁审计轨迹

报告文件被提交进 dream commit 本身 ✅（diff 首段 `new file mode`）。整梦撤销会**连这份报告一起删掉**——出事后最需要的证据被官方撤销手段销毁。

### 9. 术语泄漏与额度口径

- "经处置清单"四字在报告中**从未定义** ✅（引擎内部机制泄漏进用户界面），却正在为"`delete_policy=quarantine-first` 却直删文件"背书。"一个我看不懂的术语，正在为绕过我设的安全策略背书。"
- `max_deletes` 口径：盘上实际消失 3 个文件（引擎日志"执行删除 3 条" ✅），报告记账"删 2 · 合 1"→ 账面 2/3 有余量，按盘 3/3 顶格。**"这个口径是它自己定的，而这个定法恰好对它有利。"** 合并算不算删除额度必须写死。

### 10. 回滚命令的工程质量低于删除命令

三处"（并回补索引行）"手工尾巴（与 P3 独立同源）；`d995b02…` 出现 7 次从未说明是什么状态；**最该给 hash 的整梦撤销反而给占位符**；`git checkout -- CLAUDE.md` 无条件覆盖工作区、不进 reflog、无 dry-run、无前置检查。**"一个把'我删过你东西'当卖点的工具，它的撤销键不该比它的删除键更粗糙。现在恰恰是这样。"**

- **connection 内容是干货**："唯一真正的新增价值"——静默放水的因果链 + fail-open/closed 这个"明确、可回答、指了地方的未知"。

## Matrix ? 与 💡（择要）

**?**：被隔离的记忆日常会话还会不会被读取引用（"打标签照常喂"还是"从检索里摘出去"）——直接影响当前上下文可信度；frontmatter 顶层键（`status`/`merged_from`）与 `metadata.type` 层级不一致会不会撑爆解析器；**它有没有能力判断自己引用的记忆本身已过期**（"这可是个记忆整理工具啊"）；跑的时候工作区是否干净——脏工作区会污染"现状"证据基准；撞顶 max_deletes 是停手还是顺延明晚（后者则上限只是延缓不是约束）。

**💡**：回滚**按文件出不按笔出**，被多笔触及的文件显式标红"撤本笔会同时影响 X 笔"；发 `dream-undo` 脚本而非命令片段（含索引回补、跨笔依赖检查、dry-run）；**报告不进 dream commit**；判据栏改贴执行日志（命令+exit code+stdout 前 3 行+时间戳）"从论证变成记录"；AI 生成记忆带身份证（`origin: dream`/`confidence`/`generated_at`/`verified_at`）；**connection 用"验证清单"代替结论口吻**（把假设写成 TODO，而不是把 TODO 写成结论）；摘要加"触及文件：13（新增 2/修改 8/删除 3）"；提示行由报告同源生成；每 N 场梦出一份"自体检"复核旧隔离项与旧 connection 假设。

## 总判（原话摘要）

**观察期。** 不卸载——"合并信息保全是真的、数字账是真平的、而且它主动划出了边界，一个知道自己权限到哪儿为止的自动化工具值得给机会"。不允许——"**它的撤销键比删除键粗糙**，这一条就够了"。

观察期条款：`max_deletes=0` 三十天内一个文件都不许消失（含合并产生的删除）；`claude_md_edits=false` 待证据形态改进；connection 保留但强制 `confidence: hypothesis` + 顶部警告行，**且不许往已有记忆正文追加反链，反链只能单向从新文件指出去**；连续三十天报告动词覆盖得住 diff 才逐项放开。

**收束句**："这份报告告诉我它做了什么，但它没让我能**查证**它做了什么。前者是产品，后者才是信任。"
