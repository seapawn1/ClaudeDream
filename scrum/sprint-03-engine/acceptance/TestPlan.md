## §0 形制与边界

沿用 Sprint-1/2（判据表 H：编号／源 AC／操作化判据／测法／判定；三档退出码；AC↔H 映射确认表）。**本卷脊柱是主线七站**——PO 亲手验收只走七站，每站一行命令 + 一句话判定；H 判据按站内嵌，是 verify.mjs 的判分逻辑与打回依据（机器读，PO 不读）。守卫类判据（熔断器、删除权、feedback 保护、底片只读、零 API）全部内建 D4 负向对照——不是「跑一遍证明它对」，是「造一次坏情况证明它真会拦」。

**卷面对 developers 保密**：凡属要求已写在 SprintBacklog 第二节，只有怎么打分留在卷里；AC 之外无加码。若验收时出现本卷未声明、却决定过不过的要求，那是出卷方的错，按打回处理并修卷。

**卷成走向**：交 PO 逐段批，**验收开考前必须批过**。施工期 AC 若改（须 PO 过目），PO 会捎话来修卷；开考前 AC 冻结，之后不再变。

**贯穿说明（适用于全卷每一场梦）**：

- 零 API：每场梦都在无登录态环境跑（H-J1/J2 覆盖全卷）；冒烟检查红灯＝无登录态的**必要证据**（配合 H-J1 静态扫描与 H-J2 人工确认兜住，三者合起来才是完整证明）。
- 连跑机制：除站 4 正式场外，各场梦用环境变量覆盖 `cooldown_minutes=0` 连跑（PBI-05 备注已记录 developers 裁决支持 0 值语义）；该覆盖的报告标注即 H-A1 的可观察证据。
- 档位：全部考场梦跑 `llm_checks: off`（本轮目标形态）。

**喂料策略（定案）**：复用设计冲刺原型资产到**方案层**（PO 定案：旧冲刺 Python 代码不直接搬用）——种植方案与固定时间线取自 `scrum/.IDEO/design-sprint/Target-1-Consolidation/Prototype-01-FirstDream/testbed/build-acme.py`（acme-api 假仓库：7 个固定提交、42 记忆+MEMORY.md），判据种子取自同目录 `rot-manifest.md`（对答案卡）；**builder 以 Node 重写为 `testbed/build-testbed.mjs`**，按以下定案修正种植素材，并输出**扩展对答案卡**——判分基线一律以扩展卡为准：

## §3 接口汇总（首活——考卷接线与开考自检依据）

**3.1–3.7 提取自 [SprintBacklog.md](../SprintBacklog.md) 第二节 AC 原文（逐条标源）；3.8 来源为 DoD·D5 接口自述纪律**——考卷自身的消费需求，由 developers 在 adapter.json 声明。**考卷只消费本清单内接口**；本清单是「开考先自检」的对象——有声明未消费即报红，不许开考（ProductBacklog 第一部分第 4 节「验收流程约定」）。

### 3.1 配置文件（02.1-AC1 / AC4）

- 路径 `.claude/claude-dream.local.md`；六键与默认值：`enabled: true` ｜ `llm_checks: on` ｜ `delete_policy: quarantine-first` ｜ `max_deletes: 3` ｜ `claude_md_edits: true` ｜ `cooldown_minutes: 30`。无配置文件或缺键按默认值运行。
- 优先级：配置文件 > 环境变量；环境变量仅供测试/临时注入覆盖；覆盖生效时报告「阀门状态」节标注「本次由环境变量覆盖：`<键名>`」，不允许静默覆盖。

### 3.2 开关与档位（02.1-AC2 / AC3）

- `enabled: false` 时不拉梦，底片产线照常落底片。
- `llm_checks` 本轮 `on`/`off` 行为一致（同 `off` 语义）；报告「阀门状态」节如实标注「LLM 层待 PBI-07，本档位暂不生效」。

### 3.3 隔离标记（02.3-AC4）

- 隔离条目 frontmatter 记 `status: quarantined` + 隔离原因 + 起始信息；原文原地完整保留，去掉标记即还原原状（可逆）。

### 3.4 底片消费契约（02.6-AC2，稳定公开接口，PBI-06 重做时必须保住）

- ① 台账结构：`ledger.json` 按 sessionId 分组，每页记录含 `file` 字段，值为**文件名**而非完整路径——消费方自行与底片目录拼接。
- ② 底片页正文保留用户原话。
- ③ 用户发言在页内有稳定的、可机械识别的段落标记：`### User` ｜ `### User (meta)` ｜ `### User (steering)`。

### 3.5 G9 检索基准（02.6-AC1）

- 检索范围为**上次梦 runId 之后**产生的底片页；本轮机械检索（标识匹配：上梦隔离区/「待你裁决」对象的记忆文件名/slug）；报告收录原文引用 + 出处页指针。

### 3.6 熔断口径（02.4-AC1 / AC3）

- 计数对象＝**记忆文件净消失数**（隔离标记、纯索引行修复、非记忆文件改动不计入）；库存基准＝**梦前状态记忆文件数**；判定＝严格 `>`；阈值＝max(`max_deletes`, 库存 10%)。
- 触发后：中止整梦、记忆回到梦前状态、报告写明熔断原因/真实净消失数/被回滚动作清单；锁与标记正常释放；**冷却期照常起算**（熔断算做过一场梦）。

### 3.7 报告可观察契约（02.5 AC1–AC6）

- 明细每笔四要素：动作 ｜ 判据编号 ｜ 证据 ｜ 回滚提示。
- C2 证据两种记法：真实执行的命令→命令原文 + exit code + stdout 摘要 + 时间戳；纯代码判据→判据输入 + 判定结果 + 时间戳。报告不出现无记录支撑的论证式证据；同篇核查命令统一 shell 方言。
- C3 抽查点以梦前状态为基准、必须能失败；每笔删除内联被删正文（死者遗言）；自动挑证明力最弱的 3 笔（不足 3 笔全列）。
- 30 秒版：动作类型说全（逐类不漏）；触及 CLAUDE.md 的动作置顶展示。

### 3.8 由 developers 在 adapter.json 声明（出卷方不代填，来源 DoD·D5）
