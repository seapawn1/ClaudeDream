# Sprint-2-negatives · 验收 TestPlan（骨架）

> 本文件是出卷 fork 的起点，不是终稿。fork 继承本次 Planning 会话的全部语境，无需另立交接文件。判据表、`verify.mjs`、考场生成器留给出卷时补齐；下面只落「要求级」内容——凡出卷时可自由决定的（喂料细节、判据措辞、场景先后）都不在此列。

## §0 形制与边界

沿用 Sprint-1（`scrum/sprint-01-skeleton/acceptance/`，已实证有效）：判据表 H（编号／源 AC／操作化判据／测法／判定）＋ 场景化 ＋ 自动/人工分列 ＋ 验收规则 ＋ AC 映射确认表（对着 [SprintBacklog.md](../SprintBacklog.md) 第二节逐条勾核，一条不落）。守卫类判据全部内建 D4 负向对照——不是"跑一遍证明它对"，是"造一次坏情况证明它真会拦"。

**卷面对 developers 保密**：凡属要求已写在 SprintBacklog 第二节「交付接口约定」，只有怎么打分留在卷里；AC 之外无加码。若验收时出现本约定未写明、却决定过不过的要求，那是出卷方的错，按打回处理并修卷。

**首活＝E0·AC2**：Sprint-1 verify 在打分后改动的代码上重跑一次全绿（重建 `sprint-01-skeleton/acceptance/` 考场 + verify），输出留档本线，结论抄送 PO 转达 developers。这件事与出卷本身无关，是欠账，优先级最高。

**卷成走向**：交 PO 逐段批，**验收开考前必须批过**。施工期 AC 若改（须 PO 过目），PO 会捎话来修卷；开考前 AC 冻结，之后不再变。

## §1 场景骨架（出卷时细化为判据表 H 的具体行）

| 场景 | 考什么 | 对应 AC |
|---|---|---|
| A 正常散会 | 喂 SessionEnd stdin JSON 模拟散会 → 底片出现、一场一文件、可寻址、留/剔规则表核对（该留的在、该剔的没了）、体积达标 | 01.1·AC1/3/4 |
| B 不可变 | **同一场**再压一次（重放同一份 stdin 或重跑补捞）→ 旧底片字节不变（哈希对比）；负向对照：手工改一字节 → 对比变红 | 01.1·AC1（D4） |
| C 写失败 | 用故障注入开关造一次底片写失败 → 散会链路不炸、错误留痕且落点在底片目录之外 | 01.1·AC5（D4） |
| D 进料＋拒写 | 占位梦报告出现进料对账行（受信任代码写、含触发场 session id）；作恶模式指定底片目录内路径 → 被拒且日志可见该路径 | 01.2·AC1/2（D4） |
| E 回程检索 | 逐字稿里埋一句标记话 → 底片里按原文检索得到 | 01.2·AC3 |
| F 补捞 | 造一场无结束事件（模拟强杀）的逐字稿 → 下一个触发点补齐；梦自身逐字稿不被误压；正在进行的"活稿"不被误冻；重复补捞不产生第二页 | 01.1·AC6（D4） |
| G 零 API | 断网环境下压缩链路一键跑通 | 01.1·AC2 |
| H 并发 | 模拟两场会话同时散会 → 两页底片都在、台账不坏 | 01.1·AC6③（并发口径） |
| 人工项 | 真实环境真跑一次正常散会，亲眼看底片落盘 | 兜真实性 |

## §2 待出卷 plan 时定的问题

1. **喂料策略**（首个要拍的决定，交 PO）：SM 建议「真逐字稿冻结＋人工埋标记」——用一份本仓库或其他项目的真实会话逐字稿冻结作为固定输入，格式和噪音都是真的，人工在其中埋一句可检索的标记话作为 E 场景的标准答案，重跑时输入不变、结果确定。备选：纯手造假稿（最可控，但格式细节失真风险大）；验收现场真跑取稿（最真实，但不可重复，违背 D1「一键重跑、重跑同结果」的考场哲学）。
2. 判据表的具体测法命令、verify.mjs 的断言组织、考场生成器怎么造（是否复用 `reference/claude-code-log/` 或 Sprint-1 的 builder 形制）。
3. 是否需要在本工位内另建 `testbed/`（沿 Sprint-1 的 `build-testbed.mjs` 确定性生成器模式）。

## §3 工位与协作

出卷会话工位在 `.claude/worktrees/acceptance`（git worktree，分支 `sprint-02-acceptance`）。入位后 harness 强制拦截对主仓（`sprint-02-negatives` 工作树）的一切编辑与命令——物理隔离，非仅约定。考卷、考场、`verify.mjs`、判据表全部提交在本分支，developers 所在的施工线看不见。跨线消息（AC 改动、批卷结果、开考指令）只走 PO 的手。
